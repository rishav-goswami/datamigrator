## **AI Developer Case Study**

### **Title: AI Data Migration Orchestrator using Multi-Agent System**

### **Objective**

Design and implement a **multi-agent system** powered by LLMs that collaboratively generates, validates, and explains SQL migration scripts based on structured schema and mapping metadata.

This case study simulates a **real-world enterprise scenario** where multiple AI agents need to perform specialized tasks — similar to how an AI co-pilot might assist a data engineering team during a complex data migration project.

### **Context**

You're part of a consulting team migrating CRM data from **Raiser's Edge** to **Salesforce Nonprofit Cloud**. The process involves understanding legacy schemas, applying mapping logic, generating SQL, and validating transformations.

You're asked to build an **AI-powered, multi-agent system** that automates this flow end-to-end — no human-in-the-loop.

## **Multi-Agent System Overview**

| Agent Name | Role |
| ----- | ----- |
| **Schema Analyst Agent** | Reads the source and target schemas, extracts structure, detects mismatches |
| **SQL Generator Agent** | Generates SQL `SELECT` or `INSERT` statements using LLM |
| **Validation Agent** | Verifies data type compatibility and identifies possible errors or missing mappings |
| **Explainer Agent** | Writes a human-readable explanation of the generated SQL for auditability |

All agents use the same (or separate) LLM instances, interact via messages or files, and collaboratively produce the final output.

## **Provided Inputs**

You'll receive the following **(For now just use your own dummy data)**:

1. `source_schema.json`

2. `target_schema.json`

3. `field_mapping.csv`

These define the schema structures and mapping rules for migration.

## **Deliverables**

You must submit the following files:

1. `main.py` or `orchestrator.ipynb`

   * Orchestrates all 4 agents

   * Handles data exchange between agents

   * Produces final SQL \+ validation \+ explanation

2. `agents/` folder

   * Each agent implemented as a separate class/module

   * LLM-based logic encapsulated inside each agent

   * Use LangGraph, CrewAI, or your own coordination logic

3. `sample_output.sql`

   * Final SQL script generated by the system

4. `validation_report.md`

   * Output from the Validation Agent

   * Example: "gift\_total is decimal, but mapped to Text in Salesforce"

5. `sql_explanation.md`

   * Explanation of the SQL written by the Explainer Agent in plain English

6. `README.md`

   * Setup instructions

   * Model used (e.g., Mistral, TinyLlama, etc.)

   * Description of how multi-agent coordination works

### **Candidate FAQ**

**Q1: Do I need Salesforce, Raiser's Edge, or any database access?**
**A:** No. All work is based on the input files (`.json`/`.csv`). No special access or proprietary platforms needed.

**Q2: What LLMs or APIs can I use?**
**A:** Any LLM is fine. Use OpenAI, Hugging Face Transformers, Mistral, TinyLlama etc. If you don't have paid API access, use an open-source model.

**Q3: Is agent orchestration required to use a specific tool?**
**A:** No. You may use LangGraph, CrewAI or build your own logic in Python. Pick what you're comfortable with.

**Q4: What if I get stuck on a part? Can I submit a partial solution?**
**A:** Yes! Submit your best attempt, with clear documentation (README). Partial, well-explained solutions are evaluated on design, code quality and approach.

**Q5: How complex should the input files be?**
**A:** The sample schemas and mapping files will have a manageable number of fields (e.g., \<10 fields/tables each) for proof-of-concept. Focus is on logic, not scale. Use your own dummy data.

**Q6: Can I use open-source or trial versions of required tools?**
**A:** Yes. You're encouraged to use free/open-source tools. No commercial licenses required.

**Q7: What is the expected time commitment?**
**A:** The full solution should be submitted within 48 hours, with partial solutions accepted.

**Q8: If something is not clear, what do I do?**
**A:** Think from a business/project perspective and make reasonable assumptions.
